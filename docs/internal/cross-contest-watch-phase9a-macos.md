# Cross-Contest Watch Phase 9A macOS 最終検証

2026-11-26。検証対象は Phase 8B-1 の `1fa0982`、同条件での測定比較元は Phase 8A の `2062286`。macOS 26.6.2（25G83）、MacBook Air Apple M2（8 コア、メモリ 16 GB）、Rust 1.97.1、Python 3.14.6、notify 9.0.0、notify-types 2.3.1。比較元と対象は同じ Mac、同じローカル APFS で検証した。[OS 別検証手順](cross-contest-watch-validation.md)、[Phase 8B](cross-contest-watch-phase8b-windows.md)、[Phase 8B-1](cross-contest-watch-phase8b1-windows.md)を参照した。

**判定は Phase 9B へ進行可。** Phase 8B-1 の安全性の回帰や、公開を妨げる動作不良は確認できなかった。通常権限で全回帰が成功し、1,000 Contest のウォーム初回 Open は同条件で 479.1 → 403.7 ms。登録増減時に一度だけ観測した保存未受付は原因を確定できていない。再調査結果と適用範囲を連続動作試験に記録した。

## macOS 実機検証

リリース版の実行ファイルを 140×42 の macOS PTY に接続し、実キー・マウスイベントと実ファイルの書き込みで検証した。Global Config は正式な `[watch]` と `[runner]` を隔離した XDG の `config.toml` に設定した。Refresh・Migrate はリポジトリの AtCoder fixture を使用した。

| 経路 | 結果 |
| --- | --- |
| 保存と自動表示 | 上書き、同じ内容の再保存、Atomic Save、削除・再作成で期待する実行・表示を確認。chmod のみでは実行・自動切り替えともに発生しなかった。 |
| 複数 Contest・実行結果 | 同じ窓で別 Contest を連続保存し、後の保存先を先に実行・表示した。先に保存した非表示 Contest の Sample Test も実行し、戻ると結果が残っていた。実行中の Sample Test を別 Contest の保存で先取りし、記録した物理実行順は元 → 新 → 元。再実行で画面は移らなかった。 |
| 手動操作 | 切り替えモーダル中も非表示 Contest の Sample Test が走り、自動表示は保留された。手動確定後、保留していた保存への遷移は発生しなかった。User Input 編集中は保存先への遷移を保留し、編集終了後に切り替えた。User Input の出力と、別 Contest の保存による User Input・Stress の中断後に再開されないことを観測した。 |
| 大規模 Contest | 65 問の ON では最古の完了結果を除外した。90 問の OFF と 100 問の Standalone では、最後の完了後に先頭へ戻っても `1/1 AC` が残った。OFF では 9 件の User Input を実行後に最初の出力も再表示できた。 |
| 監視集合 | Contest の追加、振り分け先への移動、除外後の保存を試し、残った Contest を監視し続けた。未登録サブディレクトリのソースは受付しなかった。FD 上限 256 の 1,000 Contest でも末尾の Contest の Sample Test が実行できた。FSEvents の開始呼び出しを観測した 500 → 680 → 500 Contest の試行では、同じボリューム内の増減で開始回数が増えず、Home から再 Open したときに 1 回増えた。 |
| パス | ホストの大小文字を区別しない APFS では `b.py` という表記で既存の `B.py` に書き込んでも実行した。大小文字を区別する一時 APFS ボリュームでは独立した `b.py` を除外し、正規の `B.py` を実行した。どちらでも `B.py` に置いたシンボリックリンクは実行せず、通常ファイルへ戻すと受付を再開した。 |
| Refresh・Migrate | TUI の Refresh で欠けたサンプルを修復した。外部 CLI の Migrate 後、元の独自テストがバックアップに残り、待機中の TUI が新世代の保存を受け付けた。 |
| モードと端末 | Doctor は省略時の OFF を built-in と表示した。Settings TUI で ON にして Contest を開き、外部で OFF に書き換えた後も現在の画面と手動切り替えでは ON を維持し、Home からの再 Open で OFF になった。OFF、Standalone、Plain Watch は他 Contest を無視し、現在の Contest で保存を受け付けた。ON の Home 滞在中は保存を実行せず、再入場で受付を再開した。終了コード 0、代替画面の解除、カーソルとマウスモードの復元、PTY の canonical/echo 復元を確認した。 |

計測点を加えた一時リリースビルドでは、1,000 Contest の登録済みソース 1 本の通常通知を捨て、定期照合で 14.98 秒後に 1 回実行した。表示中の Contest は維持された。後着通知との重複排除と登録失敗後の健全な登録集合の復元は、全回帰の注入テストと、macOS の実パスが消失した場合の再登録テストで確認した。[監視テスト](../../src/commands/workspace_watch.rs)・[FSEvents のテスト](../../src/watcher/macos_workspace.rs)

1,000 Contest の定期指紋照合開始から 0.74 ms 後に手動切り替えを確定すると、41.65 ms で対象を表示し、監視スレッドは照合終了前に Open を処理した。Open 送信から受信までは 2.00 ms。別々の照合中に Home 復帰と終了を確定した試行では、照合の完了を待たずに 50.05 ms で Home を表示し、22.88 ms で正常終了した。
